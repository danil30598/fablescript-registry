# План языка и IDE

Статус: план уточняется. Первая цель согласована: обучение и небольшие программы. Название FableScript взято из имени папки и пока рабочее. Обсуждение синтаксиса отложено по желанию пользователя; система типов и формат IDE ещё не выбраны.

Текущий прогресс: создан первый вертикальный прототип — отдельное исполняемое ядро, CLI, пример `.fable` и расширение VS Code с запуском, подсветкой и диагностикой. Команда `print(...)` и прочие элементы прототипа не утверждают окончательный синтаксис.

## Цель

Создать язык для обучения и небольших программ с простотой повседневного использования Python, а также среду для написания и запуска программ. Предварительный ориентир на C# включает и классы с объектами, и общий стиль записи; конкретные правила будут обсуждаться позже.

Предусмотреть расширение языка библиотеками: в дальнейшем пользователь устанавливает пакет, затем подключает его модули в программе — по схеме, похожей на установку через pip и последующий import. Написание команд и конструкций языка пока не выбираем.

Простота означает минимум обязательного служебного кода, понятные ошибки и удобный запуск. Она сама по себе не требует динамической типизации. Сходство с C# не означает автоматически совместимость с .NET.

## 1. Определить устройство проекта, затем согласовать язык

Сейчас выбрать формат IDE: отдельное приложение или расширение существующего редактора, а также целевую платформу первой версии. Разделить проект на ядро языка, средство запуска, стандартную библиотеку и IDE. Загрузку модулей предусмотреть в ядре; установку пакетов — отдельным инструментом на следующем этапе.

Когда пользователь будет готов вернуться к синтаксису, обсуждать его небольшими порциями, предлагая альтернативы. До реализации ядра согласовать:

- Блоки кода: фигурные скобки или отступы; обязательность точки с запятой.
- Переменные: способ объявления, изменяемость, динамические типы либо статические типы с выводом.
- Функции: объявление, параметры, возвращаемые значения, точка входа в программу.
- Условия, циклы, списки и словари.
- Объекты: классы, создание экземпляров, поля, методы, обращение к текущему объекту.
- Отсутствующее значение, области видимости, обработка ошибок и импорт файлов.

Результат: небольшая спецификация и 6–8 согласованных программ с ожидаемым выводом. Все примеры до согласования считаются предложениями.

## 2. Сделать минимальное исполняемое ядро

Предлагаемый первый вариант — интерпретатор, запускающий файл из командной строки. Язык реализации выбрать после уточнения целевых платформ и требований к совместимости.

Последовательность: чтение файла → лексер → парсер → дерево программы → проверка правил → выполнение.

Первый сквозной пример должен выводить текст, выполнять выражение и выдавать понятную ошибку с именем файла, строкой и столбцом. Координаты исходного кода сохранять с самого начала.

Результат: рабочий путь от исходного файла до вывода программы и диагностики.

## 3. Добавить возможности первой версии

Предлагаемый объём для обучения и небольших программ:

- Числа, строки, логические значения, переменные и операции.
- Условия, циклы, функции и области видимости.
- Списки и словари.
- Простые классы с полями и методами; детали объектной модели согласовать позже.
- Импорт собственных файлов и небольшая стандартная библиотека для консоли, текста и файлов.

Проверять поведение тестами, основанными на согласованных примерах: обычные случаи, границы и ошибки. Собрать несколько законченных программ, например калькулятор, обработчик текста и пример работы с объектами.

Результат: небольшие полезные программы работают без специальных доработок интерпретатора под каждый пример.

## 4. Подключить IDE

Макет интерфейса можно готовить параллельно с ядром. Запуск и диагностика должны использовать одну реализацию языка в IDE и командной строке.

Первая версия среды:

- Открытие папки проекта и файлов, создание и сохранение файлов.
- Редактор с подсветкой синтаксиса и номерами строк.
- Запуск и остановка программы в отдельном процессе.
- Панель вывода и ввод данных для консольной программы.
- Переход от ошибки к месту в исходном коде.

Результат: пользователь может написать, сохранить, запустить и исправить программу целиком в IDE; бесконечный цикл в программе не блокирует редактор.

## 5. Подготовить версию 0.1

Добавить базовые подсказки по именам, краткую документацию, примеры и способ установки на выбранную платформу. Проверить весь путь на чистом окружении.

Результат: новый пользователь устанавливает среду и самостоятельно запускает пример по инструкции.

## Позже

### Пакеты и внешние библиотеки

Это запланированное развитие после работающего ядра и локального импорта. Модуль — подключаемая часть программы; пакет — распространяемая библиотека, которая может содержать несколько модулей.

В первой версии определить правила поиска локальных модулей и стандартной библиотеки, разрешение совпадающих имён, доступность имён снаружи, поведение повторного импорта и циклических зависимостей. Поиск модулей выделить в отдельный компонент, чтобы позже подключить установленные библиотеки без переделки обычного импорта.

Первый проверяемый результат: программа подключает второй локальный модуль и использует его функции; ошибки поиска модуля указывают причину и место импорта.

На этапе менеджера пакетов добавить:

- Описание пакета: имя, версия, совместимая версия языка и зависимости.
- Установку зависимостей отдельно для каждого проекта.
- Фиксацию точных версий, чтобы повторная установка воспроизводила окружение.
- Подключение установленных модулей через общий механизм импорта.

Начать с пакетов на самом языке из локальных папок или архивов. Публичный каталог пакетов и интеграции с библиотеками других языков оценить отдельно. Точные форматы файлов, команды и правила совместимости ещё предстоит выбрать.

### Остальные возможности

Полный отладчик, сложное наследование, интерфейсы, дженерики, перегрузки, асинхронность, оптимизирующий компилятор и развитый GUI-фреймворк — отдельные последующие этапы. Если что-то из этого необходимо для основного назначения языка, пересмотреть объём первой версии до реализации.
